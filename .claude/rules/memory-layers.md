# 记忆分层规范

## 总览

本项目采用 L0/L1/L2/L3 四层记忆模型。层级越高，越接近长期稳定认知；层级越低，越接近原始证据。

| 层级 | 含义 | 主要来源 | 是否可改写 |
|------|------|----------|------------|
| L0 | 原始会话消息 | 用户/助手/工具消息 | 不可语义改写 |
| L1 | 原子事实 | L0 抽取结果 | 可去重、可合并 |
| L2 | 场景记忆 | L1 聚合结果 | 可重写、可版本化 |
| L3 | 长期画像 | L2/L1 稳定信号 | 谨慎更新 |

## L0 原始层

L0 用于保存原始消息和工具结果，是所有后续记忆的证据来源。

要求：

- 不改写原始内容。
- 必须有稳定幂等键。
- 必须记录 `user_id`、`source_conversation_id`、`source_session_key`。
- 可通过 `metadata` 记录 role、message_id、tool_name、token_count、client_time。
- 删除应使用软删除，不直接物理删除。

禁止：

- 在 L0 中保存模型总结替代原文。
- 用非稳定随机 ID 作为重复采集的唯一依据。

## L1 原子事实层

L1 保存从 L0 抽取出的事实、偏好、约束、任务状态等原子信息。

要求：

- 内容应尽量单一，不混合多个事实。
- 必须在 `metadata.source_memory_ids` 中保留来源 L0 ID。
- 应记录 `confidence`、`extracted_at`、`extractor_version`。
- 去重时保留被合并项的 lineage。

适合内容：

- 用户偏好。
- 项目事实。
- 长期约束。
- 可复用的任务上下文。

不适合内容：

- 单次对话的临时寒暄。
- 无来源依据的推测。

## L2 场景层

L2 保存围绕项目、主题、任务、场景聚合后的记忆块。

要求：

- 必须有 `scene_name` 或等价场景标识。
- 必须记录来源 L1 ID 列表。
- 允许重写，但需要保留 `previous_memory_id` 或版本信息。
- 应支持按场景召回。

更新原则：

- 多个 L1 支撑同一场景时才生成或更新 L2。
- 新信息与旧 L2 冲突时，不直接覆盖；应记录冲突来源或降低置信度。

## L3 长期画像层

L3 保存长期稳定的用户画像、项目画像或工作方式。

要求：

- 必须有足够证据，不因单次对话直接写入长期画像。
- 必须记录 `evidence_count`、`confidence`、`last_seen_at`。
- 更新要保守，删除要可追溯。
- 适合被 recall 作为高优先级上下文。

禁止：

- 把一次性需求直接提升为 L3。
- 无证据地写入用户偏好或身份信息。

## 晋升规则

- L0 -> L1：抽取事实，必须保留来源。
- L1 -> L2：按场景聚合，必须保留 lineage。
- L2 -> L3：只提升稳定、重复出现、有明确证据的长期信息。

任何跨层派生都必须可追溯，不能产生无来源记忆。
